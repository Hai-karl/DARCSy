# Deploying to a live URL (free or student-friendly)

You will end up with three pieces, each with its own free plan:

| Piece | Service | What it hosts |
|---|---|---|
| Database | **TiDB Cloud** (free tier, MySQL-compatible) | Users, defect records, alerts, audit log |
| API | **Render** (free web service) | The Flask app in this repository |
| Website | **Vercel** or **Netlify** (free plans) | The React app in `frontend/` |

Free plans change. Check each service's pricing page before you start. At the time of writing:
- A free Render web service goes to sleep after about 15 minutes with no visitors, so the first visit after a break takes up to a minute. It also has a temporary disk, and Render's free database is PostgreSQL that expires, not MySQL. That is why the database lives at TiDB.
- PythonAnywhere's free plan is not a good fit: new free accounts have no MySQL and outbound connections are restricted, so it cannot reach an outside MySQL database.
- Vercel's free "Hobby" plan is meant for personal, non-commercial use, which covers a final year project. Netlify's free plan is a good alternative.

I could not create accounts or deploy from this chat. I checked the pieces locally instead: the app boots under gunicorn in production mode, the tests pass against MySQL 8, and the frontend builds and works against the API. **I did not test against TiDB, Render, Vercel or Netlify themselves.** Follow the steps, and if a screen differs from what is written here, trust the service's own instructions and tell me what you see.

## Step 0. Put the project on GitHub
Push the whole project (the folder that contains `backend`, `defect_analysis`, `frontend`, `render.yaml`). Check that `.env` files are not committed. `.gitignore` already skips them.

## Step 1. Create the database (TiDB Cloud)
1. Sign up at tidbcloud.com and create a **Starter** (free) cluster. Pick a region close to your Render region.
2. Create a database called `defect_qc` (SQL editor: `CREATE DATABASE defect_qc;`).
3. Click **Connect**, choose a SQLAlchemy / PyMySQL connection, and generate the password. Keep the host, port (usually 4000), user and password.
4. Build the connection string for the app:
   ```
   mysql+pymysql://USER:PASSWORD@HOST:4000/defect_qc?ssl_ca=/etc/ssl/certs/ca-certificates.crt&ssl_verify_cert=true&ssl_verify_identity=true
   ```
   Special characters in the password must be URL-encoded (for example `@` becomes `%40`). Prefer the exact string TiDB shows, and keep its SSL settings.
5. The app creates its tables on the first start. You do not need to run `schema.sql` (it is for plain MySQL servers).

## Step 2. Deploy the API (Render)
1. At render.com choose **New, then Blueprint**, connect your GitHub repository, and select it. Render reads `render.yaml`.
2. Fill in the values it asks for:
   - `DATABASE_URL`: the string from step 1.
   - `CORS_ORIGINS`: leave a placeholder such as `https://example.com` for now. You will change it in step 4.
   - `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_EMAIL`, `BOOTSTRAP_ADMIN_PASSWORD`: your first administrator. The password needs 10+ characters with a letter and a number.
3. Click deploy. The build installs the packages and trains the dataset prediction models.
4. When it is live, open `https://YOUR-SERVICE.onrender.com/api/health`. You should see `{"status":"ok"}`.
5. Remove `BOOTSTRAP_ADMIN_PASSWORD` from the Render environment settings and redeploy. The administrator already exists in the database.

If you prefer to create the administrator from your own computer instead, set `DATABASE_URL` locally to the same string and run:
```
python -m backend.manage create-admin --username admin --email you@example.com
```

`SECRET_KEY` is generated by Render. If you change it later, everyone is signed out.

## Step 3. Deploy the website (Vercel or Netlify)
**Vercel**
1. New Project, import the repository, set **Root Directory** to `frontend`. The framework is detected as Vite.
2. Add the environment variable `VITE_API_URL` = `https://YOUR-SERVICE.onrender.com` (no trailing slash).
3. Deploy. `frontend/vercel.json` makes page refreshes and direct links work.

**Netlify**
1. Add new site, import from Git, set **Base directory** to `frontend`. The build command and publish folder are read from `frontend/netlify.toml`.
2. Add `VITE_API_URL` in Site configuration, Environment variables, then deploy.

`VITE_API_URL` is baked in when the site is built. If you change it, redeploy the site.

## Step 4. Let the website talk to the API
1. Copy the website address, for example `https://defect-qc.vercel.app`.
2. In Render, set `CORS_ORIGINS` to exactly that address (no trailing slash, `https://`). Several addresses can be separated by commas.
3. Save so Render redeploys.

## Step 5. Check it works
1. Open the website and sign in as your administrator. You land on **Users**.
2. In a private window, click **Request an account**, register, and see the "waiting for approval" message.
3. As the administrator approve it, then sign in as the new user.
4. As a QC Engineer, log a defect. As a Quality Manager, open the dashboard.
5. The first request after a quiet period can take up to a minute. The sign-in page tells you when it is waking the server.

To load sample data for a demo, sign in as a QC Engineer and upload a CSV on the **Log defect** page (see the README for the columns). Do not run `python -m backend.seed` against the live database. It refuses to when `APP_ENV=production`, because it creates demo accounts with a known password.

## Security checklist before you share the link
- [ ] No demo accounts exist (a fresh database has none).
- [ ] `SECRET_KEY` is random and not in the repository.
- [ ] `CORS_ORIGINS` is your website address only.
- [ ] `BOOTSTRAP_ADMIN_PASSWORD` was removed after the first start.
- [ ] You can sign in, and a wrong password is refused.
- [ ] Only the IT Administrator can approve users.

## Other ways to run it
- **Docker:** `docker compose up --build` starts MySQL and the app on http://localhost:5000. The administrator is `admin` with the password in `docker-compose.yml`. Change it. The same `Dockerfile` works on any host that runs containers.
- **Local development:** run the API with `flask --app backend.app run` and the website with `cd frontend && npm install && npm run dev`. Copy `frontend/.env.example` to `frontend/.env`. Put `CORS_ORIGINS=http://localhost:5173` in the API's `.env`.

## Troubleshooting
| Problem | Likely cause and fix |
|---|---|
| Browser console shows a CORS error | `CORS_ORIGINS` does not exactly match the website address. Fix it and redeploy the API |
| "Cannot reach the server" | The free API is waking up. Wait a minute and retry. Also check `VITE_API_URL` is correct and was set before the site was built |
| API fails to start and the log says `SECRET_KEY` or `CORS_ORIGINS` | Production mode refuses unsafe settings. Set both |
| Database connection errors | Re-check the connection string, URL-encode the password, and keep the SSL parameters |
| Dashboard says the model is not trained | Root cause suggestions need at least 30 labelled defect records. The app retrains at start when enough exist |
| You were locked out after wrong passwords | Wait 15 minutes, or ask an administrator to reset your password |
| Page refresh shows 404 on the website | The rewrite file is missing. Keep `vercel.json` or `netlify.toml` in `frontend/` |
